OwliaBot 使用**三层密钥安全模型**，在自动化与安全之间取得平衡。

## 问题是什么

加密自动化存在风险：
- 持有私钥的机器人可能清空钱包
- 机器人“作恶”会导致 Rug Pull
- 用户想要自动化，但又害怕丢失资金

## 解决方案：三层模型

### 第一层：用户确认（伴生 App）

适用于**任何重要交易**。

```
Bot → [推送请求] → App → [用户确认] → 签名 → 广播
```

- 私钥**永不离开**移动端 App
- 需要生物识别 / PIN 确认
- 用户可以看到完整交易详情
- 安全性最高

### 第二层：会话密钥（本地、一次性）

适用于**小额自动化操作**。

- 由机器人本地生成
- 有金额上限（例如每笔最多 $10）
- 定期轮换
- 泄露 = 损失受限

使用场景：Gas 支付、小额领取奖励、打赏转账等。

### 第三层：智能合约钱包

适用于需要程序化控制的**大额自动化操作**。

```
┌─────────────────────────────────────────┐
│ 智能合约钱包（ERC-4337）                │
│                                         │
│ 会话密钥权限：                           │
│ - 仅白名单合约                          │
│ - 每日 / 每笔限额                        │
│ - 仅特定代币                            │
│ - 时效限制                              │
│                                         │
│ Owner Key：                             │
│ - 随时撤销会话密钥                      │
│ - 提走全部资金                          │
│ - 修改权限规则                          │
└─────────────────────────────────────────┘
```

使用场景：DeFi 策略、周期性换币、收益优化等。

## 安全原则

### 1. 私钥隔离

主私钥**绝不进入机器人进程**。就这么简单。

### 2. 最小权限

会话密钥只拥有完成任务所需的最小权限。

### 3. 可撤销

用户可以随时瞬间撤销任何会话密钥。

### 4. 可审计

所有操作都可记录、可追踪。

### 5. 金额限制

自动化操作具备可配置上限。

## 对比

| 方式 | 风险 | 自动化 |
|------|------|--------|
| 把私钥交给机器人 | 🔴 可能全损 | ✅ 完全自动化 |
| 仅第一层 | 🟢 用户全程确认 | ❌ 手动为主 |
| 第二层（会话密钥） | 🟡 受限于上限 | ✅ 小额自动化 |
| 第三层（智能钱包） | 🟢 细粒度控制 | ✅ 大额自动化 |
